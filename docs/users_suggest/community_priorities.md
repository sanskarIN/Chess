# Community priority process

Chess-Master does not use paid votes, local coins, social-media reactions, or
issue spam as an automatic roadmap. Maintainers may periodically group
well-specified candidates and request feedback on user impact and tradeoffs.

Priority evidence can include repeated independently described problems,
accessibility blockers, correctness defects, security risk, maintenance burden,
and contribution readiness. Raw vote counts are advisory and can be distorted.

The public feature catalog must keep `Available`, `Beta`, `Planned`, and
`Premium candidate` meanings factual. A suggestion stays planned until code,
tests, documentation, and release evidence exist. “Premium candidate” never
means a purchase exists or that local reward coins have monetary value.
