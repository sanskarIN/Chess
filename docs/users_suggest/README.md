# User suggestions

Suggestions are welcome, but a submitted idea is not a promise, roadmap
commitment, ownership transfer, or evidence that a feature exists.

Use the GitHub feature-request form. For private security issues use
SECURITY.md; for support use SUPPORT.md; for translations use
`docs/translations/contributing.md`.

## A useful suggestion contains

- the user problem and who experiences it;
- an observable proposed experience rather than only a technology choice;
- chess-rule, notation, clock, synchronization, and abuse edge cases;
- offline and degraded behavior;
- accessibility and localization needs;
- privacy, permissions, storage, network, and deletion impact;
- dependency/asset/service source and license;
- testable acceptance criteria and ongoing maintenance cost.

Maintainers triage suggestions using [triage.md](triage.md). Accepted ideas
still require design, implementation, tests, documentation, and release review.
Rejected or deferred ideas remain available under the issue’s terms; personal
information should not be included.
